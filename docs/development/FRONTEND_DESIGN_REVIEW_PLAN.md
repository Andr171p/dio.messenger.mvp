# DIO Chat — ревью фронтенда и план исправлений

24 ноября 2026 · версия кода `2119062` · React, messenger-core, messenger-ui, маршруты FastAPI.

## Статус реализации

Адаптивные панели, изоляция состояния сессии, черновики и восстановление сообщений исправлены. История загружается страницами. Из поиска, цитаты и закрепа можно перейти к сообщению. Цитата передаётся как опциональное поле `quoteText` вместе с `replyToId`. Messenger проверяет, что оригинал видим отправителю и содержит выбранный фрагмент. Подтверждённый фрагмент сохраняется в JSON сообщения и участвует в проверке повторной отправки. Миграция для цитат не требуется.

Для вложений используются статусы медиаворкера. Поиск и карточки заявок подключены к существующим API DIO Desk. Сводка включает описание, актуальность, метаданные вложений и историю, когда поставщик возвращает эти данные. Индекс DIO Desk ищет по заголовку и описанию. Поиск по префиксу номера, SLA и просмотр содержимого вложений заявки требуют отдельных контрактов. Прочтение показывается как агрегат по доступным курсорам. Имена и точное время отдельных прочтений зависят от политики доступа и отдельного серверного источника времени.

Ниже сохранён исходный аудит для трассировки задач к макетам и снимкам до изменений.

Начать с сохранности переписки и адаптивных панелей. На ширине 1024 px открытие заявки полностью убирает чат. После перезагрузки теряется черновик. При восстановлении истории собственное сообщение становится входящим. Эти три дефекта воспроизведены на текущем фронте и исправляются на клиенте.

## Ревью кода и порядок поставки

1. **Первый набор изменений — сохранность данных.** Помимо черновиков и восстановления истории, ограничить жизненный цикл React Query текущей сессией. Сегодня экземпляр общий, а ключ поиска содержит только запрос. После смены аккаунта возможен показ результата предыдущего пользователя из свежего кэша. При смене аккаунта и отзыве доступа отменять запросы и очищать соответствующие данные и открытые панели. Добавить регрессии для смены аккаунта, черновика, поздней загрузки, snapshot и подтверждения внешней пересылки. [QueryProvider](../../messenger.web/apps/messenger/src/app/providers/QueryProvider.tsx) · [Состояние интерфейса](../../messenger.web/apps/messenger/src/stores/uiStore.ts)
2. **Второй набор — адаптивный каркас и визуальная сверка.** В одном изменении согласовать режим CSS и семантику доступности. На одном наборе данных снять 1360 × 840, 1024 × 840, 760 × 840 и 390 × 844 в обеих темах, с закрытой и открытой заявкой. Проверить ширины непосредственно по обе стороны 600, 900 и 1240 px. Принимать по композиции, читабельности, доступности действий и сохранению позиции переписки.
3. **Третий набор — поиск и действия по сообщению.** Разделить нынешний `MessageTimeline` на ленту с позиционированием, пузырь с блоками и меню действий. В редакторе отделить состояние черновика от жизненного цикла загрузки и выбора `@`/`#`. Вынести повторяющиеся запросы к участникам, заявкам и медиа в типизированные функции на основе имеющейся OpenAPI-схемы. Сохранить границы пакетов и атомарную запись сообщения с outbox в Dexie. Приёмка — поиск → старое сообщение → ответ → возврат, включая touch и клавиатуру. [Имеющиеся типы API](../../messenger.web/packages/messenger-core/src/transport/generated/messenger-api.d.ts)
4. **Четвёртый набор — интеграция и приёмка двумя пользователями.** Подключить доступные API участников, медиа, заявок и курсоров. Согласование новых контрактов цитат, SLA, поиска заявок и детальных прочтений можно начать одновременно с первым набором. Проверить обычного сотрудника и гостя, повторное открытие после переподключения, отказ в доступе и работу с внешним адресатом. Треды, опросы и отложенную отправку вести по существующему плану итераций. [План итераций](FRONTEND_PRODUCTION_ITERATIONS.md)

**Результаты проверок на исходной версии.** TypeScript приложения прошёл. У messenger-core прошли 8 тестов. Существующий Playwright smoke проверяет форму входа и прошёл в системном Chrome. Для запуска использован временный конфиг, поскольку ожидаемый Playwright Chromium отсутствует. ESLint вернул одну ошибку `prefer-const` в `syncEngine.ts` и два предупреждения Fast Refresh в провайдерах. Основные пользовательские регрессии выше выходят за покрытие этого smoke-теста.
