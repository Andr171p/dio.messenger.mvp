# Чаты, профили и темы

Проект ветки `feature/chat-management` от 25 ноября 2026 года. Документ описывает поведение продукта, решения в рабочей ветке и проверки перед выпуском. Изменения IAM относятся к `C:\Users\andre\diodesk_fork_prod_version`.

## Как пользователь перемещается между экранами

| Откуда | Действие | Результат |
| --- | --- | --- |
| Список чатов | Нажать «Новый чат», найти человека | Открывается профиль с фото, именем, логином и кнопкой «Написать сообщение». Нажатие открывает существующую переписку пары или создаёт первую. |
| Личная переписка | Нажать на имя или фото в заголовке | Открывается профиль собеседника. Закрытие возвращает к переписке. |
| Группа | Нажать на название или фото в заголовке | Открывается карточка группы. Сверху фото, название и введённое описание. Ниже участники, их роли и доступные статусы присутствия. |
| Карточка группы | Выбрать участника | Открывается его профиль. Закрытие возвращает в карточку группы. Кнопка «Написать сообщение» открывает личный чат. В собственном профиле доступна смена фото. |
| Группа | Открыть «Темы» | На широком экране список тем занимает левую колонку, переписка остаётся справа. На телефоне выбор темы открывает её ленту. «Все чаты» возвращает к списку бесед. |

Названия, аватары и строки участников доступны с клавиатуры. У диалога есть заголовок и кнопка закрытия. Приёмка включает Escape, возврат фокуса к исходной кнопке, управление без мыши и обе цветовые темы.

## Создание группы

**Шаг 1. Оформление.** Вкладка «Группа» открывает выбор фотографии, обязательное название и необязательное описание. После выбора фото пользователь видит квадратную миниатюру в круге. Кнопка «Далее» доступна сразу. Если название состоит из пробелов или пусто, фокус переходит в поле. Красная рамка и `aria-invalid` обозначают ошибку. Отдельное всплывающее сообщение здесь избыточно.

**Шаг 2. Участники.** Поиск работает по ФИО, логину и почте. Выбранные люди остаются над результатами при смене запроса. Можно убрать человека или вернуться к оформлению с сохранением выбора. Только «Создать группу» отправляет название, описание, фотографию и состав одним запросом. Во время отправки повторное нажатие блокируется. При сетевой ошибке форма остаётся открытой.

Для первой версии предлагается разрешить группу с одним создателем. Это поддерживает сценарий, когда человек сначала готовит рабочее пространство. Внешних пользователей нужно включать в состав с гостевой ролью.

## Состояния и тексты

| Условие | Что видит пользователь | Что делает клиент |
| --- | --- | --- |
| Первый вход, локальной истории ещё нет | «Загружаем сообщения…» | Показывает состояние загрузки до ответа. Пустой чат показывает после успешного ответа. |
| Подключение пропало, история доступна | «Вы офлайн. Отправим сообщения, когда появится связь.» | Сохраняет историю на экране и принятые к отправке сообщения в очереди. |
| Сервер временно недоступен | «Связь с сервером прервалась. Пробуем подключиться снова.» | Проверяет связь автоматически. После восстановления сверяет доступ и отправляет очередь. Пользователю не требуется нажимать «Повторить». |
| Поиск завершён без совпадений | «По этому запросу никого не нашли.» | Оставляет запрос доступным для редактирования и сохраняет выбранных участников. |
| Операция требует другого файла | «Выберите фото размером до 5 МБ» или «Выберите JPEG, PNG или WebP» | Показывает подсказку рядом с выбором фото. Предыдущее фото остаётся до успешного сохранения. |
| Первая запись в теме ещё не появилась | «В этой теме пока нет сообщений.» | Открывает редактор сообщения. Черновик общего чата доступен при возврате. |

При приёмке отдельно проверить отказ в доступе, отсутствие сети и неподдерживаемый файл. Для каждого случая интерфейс должен предлагать действие, которое действительно может помочь.

## Данные и совместимость

**Имя собеседника.** Сервер возвращает `peerId` относительно вошедшего пользователя. Затем клиент читает конкретный профиль IAM по ID. Порядок отображения — ФИО, логин, почта. Если IAM временно недоступен, клиент использует сохранённое имя, затем нейтральную подпись «Личный чат». Важно проверить обе стороны одной переписки, старый кэш с UUID, поиск и окно пересылки. Назначение общего имени всей личной беседе привело бы к разным результатам для её двух участников.

**Фотография пользователя.** Владелец данных — IAM форка Desk. И форма Desk, и «Мой профиль» в Messenger обращаются к `POST /api/v1/users/me/avatar` с multipart-полем `file`. Пользователь определяется по сессии. Обработчик проверяет изображение и сохраняет в существующем `avatar_url` миниатюру JPEG 192 × 192. Этот вариант не требует отдельной миграции Desk. Перед выпуском измерить размер ответа каталога с реальными фотографиями, поскольку миниатюры передаются вместе с профилями.

**Фотография и описание группы.** Эти данные принадлежат Messenger. Старые группы допускают пустые значения. Фото группы и изменение собственного фото — разные действия с разными правами.

**Темы.** «Общий чат» соответствует сообщениям с пустым `threadId`. Именованную тему можно создать в пустой группе. Ранее созданные треды с корневым сообщением сохраняют привязку. Сервер отбирает историю по чату, области видимости участника и теме до применения лимита страницы. Запрос истории без фильтра сохраняет прежний смысл для старых клиентов. Подробнее о базовом контракте в [DEC-0015](../decisions/DEC-0015-threads-polls-scheduled.md).

**Черновики и отправка.** Для темы ключ черновика включает аккаунт, беседу и тему. Общий чат сохраняет прежний ключ. `threadId` проходит через локальное сообщение, очередь, отправку вложений, историю сервера и проекцию событий. При переходе по результату поиска в другую тему клиент сначала выбирает её, затем прокручивает к сообщению.

## Очерёдность доводки и критерии приёмки

| Этап | Работа | Наблюдаемый результат |
| --- | --- | --- |
| 1. IAM и личные чаты | Проверить загрузку фото по сессии, обновление профиля и восстановление имени из старого кэша | Два пользователя видят друг друга по имени. Пользователь за пределами первой страницы каталога находится по поиску. Фото, обновлённое в Desk, появляется в Messenger, и наоборот. |
| 2. Карточки и создание группы | Пройти создание, возврат на первый шаг, открытие карточки и переход к участнику | После перезагрузки у второго участника видны состав, название, описание и фото. Ошибка запроса сохраняет данные формы. |
| 3. Темы и история | Проверить пустую группу, существующий тред, две именованные темы и общий чат | После переключения, офлайна и перезагрузки тексты, файлы, голосовые и черновики остаются в выбранной теме. Переход из поиска, цитаты и закрепа приводит к исходному сообщению. |
| 4. Сеть и доступность | Пройти первый запуск, потерю связи, восстановление и отзыв доступа на телефоне и десктопе | Нет мигания пустой истории при фоновом обновлении. Очередь возобновляется после проверки прав. Клавиатурой можно создать группу и вернуться из профиля к участникам. |
| 5. Выпуск | Проверить миграцию Messenger на базе с существующими группами и тредами. Развернуть API профиля Desk и миграцию Messenger перед новым веб-клиентом | Старый клиент продолжает читать историю. Новый клиент проходит сквозной сценарий под двумя отдельными учётными записями. |

### Состояние проверки в рабочей ветке

- Полная цепочка миграций Messenger прошла на отдельной базе PostgreSQL 18. С запущенными HTTP API Messenger и IAM форка Desk, PostgreSQL, Redis и RabbitMQ прошёл 81 серверный тест, включая проверку доступа к чужой беседе.
- На стенде два пользователя вошли через обычный маршрут авторизации Desk. Фото, загруженное первым пользователем, второй получил через профиль Desk и каталог Messenger. Неверный файл вернул HTTP 422, предыдущее фото сохранилось. Одновременные запросы на создание личной переписки с обеих сторон вернули одну беседу и корректные идентификаторы собеседников.
- Второй участник прочитал данные группы и создал именованную тему. Проверены список участников, сохранение номера события темы и раздельная выдача сообщений общего чата и темы. Запрос без фильтра вернул обе записи.
- В клиенте прошли проверка типов, production-сборка и 23 модульных теста. ESLint завершился с тремя предупреждениями Fast Refresh. В Chromium на production-сборке прошли все 24 браузерных сценария, включая работу установленной PWA офлайн. В этих сценариях ответы API задаёт Playwright.
- В Desk прошли два новых теста формирования фото. В более широком прогоне тестов мапперов, токенов и приглашений остались 11 падений, воспроизведённых на чистом HEAD форка. В полном наборе IAM также есть ошибки сбора в двух модулях с устаревшими импортами. Это отдельная работа по тестам Desk.
- Для выкладки необходимо поставить зафиксированные зависимости форка Desk, применить миграцию Messenger командой `alembic upgrade head` и затем обновить веб-клиент. Проверки выполнены на изолированном стенде.
