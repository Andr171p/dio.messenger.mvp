# Ревью фронтенда DIO Messenger

Дата проверки — 23 ноября 2026 г. Ревизия — `50ff387`.

До пилота приоритетны отзыв локального доступа, корректность realtime и изоляция черновиков между беседами. Эти дефекты затрагивают конфиденциальность и целостность переписки.

Требования сверены с [архитектурой фронтенда](../architecture/FRONTEND_ARCHITECTURE.md), [UI/UX-дизайном](../design/UI_UX_DESIGN.md), [стандартами фронтенда](../development/FRONTEND_CODE_STANDARDS.md), [ADR по offline-first](../adr/ADR-0004-offline-first-client.md), [DEC по snapshot и отзыву доступа](../decisions/DEC-0006-snapshot-and-access-revoke.md) и [статусом MVP](../status/STATUS-frontend-mvp.md). Контракты проверены по фактическим обработчикам backend.

## Безопасность и целостность

| Приоритет | Наблюдение и влияние | Исправление |
|---|---|---|
| P1 | **Отзыв доступа оставляет локальную историю доступной.** WS-клиент отбрасывает `access.revoked`, поскольку в нём нет `eventSeq`. Manifest обновляет только присутствующие беседы. История, черновики и команды исключённой беседы остаются в IndexedDB. | Обрабатывать отзыв отдельно от нумерованных событий. При reconnect сверять список доступных чатов с manifest и блокировать или очищать локальную проекцию согласно политике. [Разбор WS](../../messenger.web/packages/messenger-core/src/transport/websocketClient.ts#L33) · [Применение manifest](../../messenger.web/packages/messenger-core/src/sync/syncEngine.ts#L131) |
| P1 | **Realtime искажает историю.** Клиент сначала разбирает вложенный payload, теряет внешний тип и подставляет `message.created`. Сервер передаёт компактные метаданные. В Edge создание записало пустой текст, а удаление оставило запись видимой. Курсор уже продвинулся, поэтому дельта пропустит событие. | Сохранять тип конверта. По компактному уведомлению получать полную дельту до фиксации курсора. [WS-клиент](../../messenger.web/packages/messenger-core/src/transport/websocketClient.ts#L165) · [Курсор](../../messenger.web/packages/messenger-core/src/sync/applyEvent.ts#L27) · [Формат backend](../../messenger.back/src/infra/realtime/fanout.py#L28) |
| P1 | **Черновик переходит в другую беседу.** В Edge текст из A появился в B. Через 300 мс он сохраняется под ID беседы B и может заменить её черновик. Цель ответа и режим редактирования тоже сохраняются при переключении. В результате текст внутреннего чата может попасть в гостевой. | Привязать состояние редактора и отложенные записи к исходной беседе. [Редактор](../../messenger.web/apps/messenger/src/features/composer/MessageComposer.tsx#L32) · [Смена чата](../../messenger.web/apps/messenger/src/stores/uiStore.ts#L58) |
| P1 | **Восстановление истории неполное.** Синхронизация читает одну страницу до 50 событий. При `409 snapshot_required` клиент не запрашивает snapshot. При `historyFromSeq > 1` новый участник может упереться в проверку последовательности, а ошибка одной беседы прерывает обработку следующих. | Догонять курсор до границы из manifest, восстанавливать snapshot с сохранением Outbox и учитывать разрешённую границу истории. [Sync Engine](../../messenger.web/packages/messenger-core/src/sync/syncEngine.ts#L155) · [Проверка последовательности](../../messenger.web/packages/messenger-core/src/sync/applyEvent.ts#L17) · [Пагинация API](../../messenger.back/src/application/messaging/queries.py#L59) |
| P1 | **Состояние сессии расходится с состоянием токенов.** После ошибки refresh runtime очищает токены через адаптер, но React продолжает считать пользователя вошедшим и показывать локальные данные. При обычной перезагрузке сессия из памяти исчезает, поэтому ранее загруженная история недоступна офлайн. | Объединить переходы состояния авторизации и согласовать восстановление сессии с политикой офлайн-доступа. [Обработка 401](../../messenger.web/apps/messenger/src/app/providers/RuntimeProvider.tsx#L53) · [AuthProvider](../../messenger.web/apps/messenger/src/app/providers/AuthProvider.tsx#L29) · [Защищённый маршрут](../../messenger.web/apps/messenger/src/app/router/AppRouter.tsx#L7) |

## Расхождения с API

- **Ответ на сообщение.** Composer отправляет `localId` в `replyToId`, а сервер ищет сообщение по серверному ID. Outbox повторяет запрос после `404`. Для отправленного сообщения нужен `serverId`, для ожидающего подтверждения — зависимость от его ACK. [Редактор](../../messenger.web/apps/messenger/src/features/composer/MessageComposer.tsx#L68) · [Backend](../../messenger.back/src/application/messaging/commands.py#L69)
- **Реакции.** Клиент делает `POST` на маршрут, который поддерживает только `GET`. Добавление и снятие имеют разные методы и пути. Локальная реакция расходится с сервером, а `405` продолжает повторяться. [Outbox](../../messenger.web/packages/messenger-core/src/outbox/outboxProcessor.ts#L157) · [Маршруты](../../messenger.back/src/api/routers/user/reactions.py#L16)
- **Удаление чужого сообщения.** Кнопка доступна во входящих сообщениях. Клиент сразу стирает локальный текст, backend отклоняет запрос, а содержимое не восстанавливается. [Кнопка](../../messenger.web/apps/messenger/src/widgets/MessageTimeline.tsx#L253) · [Оптимистичное удаление](../../messenger.web/packages/messenger-core/src/commands/deleteMessage.ts#L22) · [Проверка автора](../../messenger.back/src/application/messaging/commands.py#L307)
- **Превью заявки.** Фронт отправляет `diodesk` и номер `INC-…`. API ожидает `dio-desk` и UUID. Запрос также не передаёт `conversationId`, по которому сервер определяет гостевой режим. Все три поля нужно согласовать вместе, используя типизированную ссылку. [Запрос](../../messenger.web/apps/messenger/src/widgets/ContextResourcePanel.tsx#L24) · [Проверки backend](../../messenger.back/src/application/itsm/queries.py#L35)
- **Вложения.** После загрузки редактор вставляет `[media:…]` в текст. Получатель видит строку без возможности открыть файл. Статус MVP фиксирует упрощение, а интерфейс показывает обычную кнопку вложения. [Редактор](../../messenger.web/apps/messenger/src/features/composer/MessageComposer.tsx#L91) · [Сериализация](../../messenger.web/packages/messenger-core/src/outbox/outboxProcessor.ts#L123)

## Проверки и ограничения

- TypeScript прошёл для приложения и обоих пакетов. ESLint завершился с двумя предупреждениями Fast Refresh. Все четыре теста ядра прошли.
- В Edge на синтетических чатах и подменённом API подтверждены перенос черновика, дефекты вёрстки и ленты, преждевременная отметка прочтения, потеря текста и игнорирование удаления при обработке WS.
- Контракты и остальные замечания проверены статически. Нагрузочных замеров на реальной истории и сквозного прогона с живыми IAM и backend в рамках ревью не было. Штатный Playwright smoke проверяет форму входа. [Smoke-тест](../../messenger.web/apps/messenger/e2e/smoke.spec.ts#L3)
